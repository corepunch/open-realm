# Robo-Goblin configured passive availability

Payoff375 remains within SEP-01.2. It covers the concrete Robo-Goblin (`ANrg`)
producer under real map-authored `Misc/MorphAlternateDisable=0` and `1`. It does
not establish equivalent behavior for other Morph subclasses or close Mount
reachability and the remaining counted-owner compositions.

The retail corpus has twelve complete captures: two instrumented observations
and one independent observer-free control for each of four map/settings. Two
maps cover existing, late-attached and initially alternate Permanent
Invisibility (`Apiv`); two distinct detach maps cover removal during the pending
forward transition and from the active alternate. Each ordinary capture has
221 public markers; each detach capture has 152. Public rows match exactly
against both repeats and the controls. Across the four reference observations,
the complete projection retains 746 public markers, 804 native events and eight
literal reported pre-start system exceptions, for 1,558 records. Every
instrumented capture contains two such exceptions outside `game.dll`; the
handler returns false, and complete active/public streams follow. Their cause
and OS-fault unreachability are not established.

The observer player is an enemy: both passive-alliance directions, shared
vision and shared control are explicitly cleared. Both settings have positive
enemy-invisibility controls before the forward order. Public forward, reverse
and detach orders are accepted. The alternate type is `Nrob`, the base `Ntin`.
Both ordinary directions retain their source type for the exact `.375` primary
transition. An initially alternate attachment acquires synchronously without a
transition timer. The authored stock `DataB1=1` is retained; the duration is
`.375`, positive lifetime zero and Apiv fade `.625`.

The concrete RTTI descriptor `6fd23e1c`, complete object locator `6fc24ee8` and
primary table `6fb344c4` establish the Robo-Goblin class. Its policy slot `+41c`
at `6fb348e0` points to common `6f54c640`, rather than Burrow's unconditional
policy. The twelve ordinary policy returns and eight detach returns per
observation are all zero or all one according to the map's actual setting.
Under setting one, forward completion acquires passive availability at the
completion frontier; late attachment is already disabled, and the reverse hold
retains that owner. Reverse completion releases it and starts the authored
passive fade. Setting zero retains passive availability, including the native
retained-contribution refresh documented for [common Morph](common-morph-passive-availability.md).

The concrete removal slot `+a4` at `6fb34568` points to common `6f540e30`.
Both pending-forward and active alternate `UnitRemoveAbility(ANrg)` restore the
base synchronously and leave Unit198 zero. Setting zero returns with the live
Apiv contribution fully invisible and no fade handles. Setting one returns with
a live contribution, nonzero owned fade objects and no invisible publication;
later positive public samples witness fade completion. The complete common
removal/completion/reverse/release functions were exported, annotated, saved and
read back. Native guards cover 3,572 instruction sites and nine data ranges,
including the actual policy/removal slots and RTTI chain.

The source shares the existing configured Morph initialization, completion and
detach helpers with Bear/Raven. Only the `ANrg` parent in the ground-Morph
handler invokes them; Burrow and Submerge retain their unconditional overrides.
Deferred rebind cannot acquire the owner before native completion. Detach
completes any pending transition, restores the base while the owner is held,
then releases it. Existing saved `morph_owned` and counted availability fields
carry ownership; no serialized field or format change is introduced.

The portable contract preserves every scalar word, literal stable identity,
clock, sequence and public row. Only Unit128/12c handles use the proven
concurrent-holder lifetime projection from [common Morph](common-morph-passive-availability.md).
Last-holder literal-zero observations retire a token; concurrent aliases remain
one object, and address reuse starts a new lifetime. The raw pointer values and
per-capture retirement ledgers remain in the original bundle. Ordinary zero
runs retire 28 objects; ordinary one runs 16; each detach run 16. Both full
projected repeat streams match, without dropping allocator differences or
exceptions. The bundle also retains the failed shell launch diagnostic, which
failed before any game launch. Source, controller, map and raw capture/preload
hashes are pinned, and all four maps rebuild byte-for-byte.

The regression fixture loads the existing zero/one nested Morph374 MPQs through
priority archives and the production Misc file list, asserting literal config
metadata. Both TFT and RoC rank-one columns are exercised, including explicit
`DataB1`/`Data12=1`. The original 36 cases cover all passive modes and live
alternate/reverse save frontiers; the detach extension adds 16 pending/active
removal cases. Save checks use in-process `WriteGame`/`ReadGame` only: this is not
a fresh-process restoration claim.
