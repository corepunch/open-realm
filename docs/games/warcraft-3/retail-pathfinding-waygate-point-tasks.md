# Waygate target Move and Smart point tasks

Explicit Move and Smart to an active Waygate create two ordinary physical Move
point tasks: the entrance followed by a captured exit. The tasks have zero
requested range and no borrowed target association. An inactive gate produces
only the entrance task. The public heads remain Move 851986 and Smart 851971.

The entrance task uses the normal movement scheduler. Its portal route reads
the live gate edge when relocating the actor. Changing the destination before
arrival therefore relocates to the new edge, then the retained second task
moves toward the original cached exit. The continuation belongs to each unit independently of its physical cohort;
it does not manufacture another public command or consume a user FIFO slot.

The original four-scene family and supplemental Smart-retarget family retain
four complete observations and two observer-free controls. Both complete repeat
projections match: 6,699 semantic records and 1,045 public markers. Saved Ghidra
exports and readbacks cover 14 complete functions and 2,009 original DLL
instruction guards. Only explicitly enumerated storage pointers normalize:
the single mover storage, identity-bound producer/task unit pointers and the
unit bridge at offset 0x164. Commands, identities, callers, clocks, float words,
flags and every other field remain literal.

A third selected-group composition proves that the task sequence survives
physical cohort reconstruction. Real selected Move and Shift target Move retain
the same two-word previous request identity. The scripted entrance admission
and the peer's later queued activation both accept an exact-goal/category peer.
The source keeps its entrance task while both units bind to a new physical
group. A destination change between admissions gives the units different cached
exits; each consumes its own second point task after that shared entrance.

The cohort family retains two observations and an observer-free control. Every
one of its 3,139 ordered observer records from the fixed public prop-window
resume at tick 40 through cleanup at tick 275 matches. The first observation
matches all 288 control markers; the second matches all 243 interval markers.
Initial UI timing differs before that interval, and all raw startup rows remain
in the bundle. Only mover heap storage normalizes, with a bijective binding to
the three canonical units. Request/task identities, unit pointers, callers,
clocks and every scalar word remain literal. The union covers 19 complete
functions and 2,345 original instruction guards. These totals distinguish the
two complete original families from the explicitly bounded cohort transaction.

The original group-owned continuation proposal failed five genuine cohort
assertions before the per-unit implementation. A separate two-unit case with
no shared history then failed three ownership assertions before the native
sentinel-identity guard. Both warm/cold cases now pass, and stopping one unit
preserves the other unit's pending task. These baselines and all setup checks
are preserved separately from the earlier producer and callback failures.

The target-owned ability dispatcher delegates to the same producer. Its former

The three old serialized Waygate movement fields remain in the schema with

Legacy state, alias, allocation, activation, queue, Stop/Hold and save checks
