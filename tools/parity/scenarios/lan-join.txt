# LAN pair on one machine: the scenario starts a host, the host creates a game, a second instance ("guest") finds it
# and joins, and the host's lobby reports that guest by name. The guest then cancels, the host frees the slot, and the
# guest joins the same host a second time. Frame names and engine log lines only (locale independent).
# Both instances use their own UDP game_port, so only this host answers the guest's LAN query and other LAN games on
# the network are not listed. The guest uses the same WC3DATA; its state is "$WC3_DRIVE_STATE-guest". If a step fails,
# `run` stops both instances and keeps their logs.
#   WC3DATA=... tools/parity/wc3_drive.sh run tools/parity/scenarios/lan-join.txt
start -roc +set game_port 28111
# Host: LAN -> Create Game -> default map -> lobby.
uiwait LocalAreaNetworkButton 40
uiclick LocalAreaNetworkButton
uiwait CreateButton 10
uiclick CreateButton
uiwait PlayButton 10
uiclick PlayButton
uiwait StartGameButton 15
# Only lobby updates after this point count, so an earlier guest's line cannot satisfy the check below.
mark
# Guest: same edition and port, LAN -> Join.
as guest start -roc +set game_port 28111 +set name wc3drive-guest
as guest uiwait LocalAreaNetworkButton 40
as guest uiclick LocalAreaNetworkButton
as guest uiwait JoinButton 15
as guest uiclick JoinButton
as guest uiwait ChatEditBox 15
# The host's client sees this guest as a human player in an occupied slot.
waitlog 15 ^ +client lobby slot [0-9]+: occupied=1 .* type=human .*name="wc3drive-guest"$
shot lan-join-host
as guest shot lan-join-guest
# Guest leaves: back to the game list, and the host opens its slot again.
mark
as guest uiclick CancelButton
as guest uiwait JoinButton 15
waitlog 15 ^ +client lobby slot 1: occupied=0 .* type=open
# Guest joins the same host again and takes the slot back.
mark
as guest uiclick JoinButton
as guest uiwait ChatEditBox 15
waitlog 15 ^ +client lobby slot [0-9]+: occupied=1 .* type=human .*name="wc3drive-guest"$
shot lan-rejoin-host
as guest stop
stop
